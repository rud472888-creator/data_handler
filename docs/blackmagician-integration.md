# Blackmagician 촬영 모드와 백업 검토

프로젝트를 선택한 뒤 상단 **Blackmagician**을 누릅니다. **초대 코드**에 8자리 코드를 입력하거나 **세션 ID** 방식으로 연결합니다. ID의 대소문자는 보존됩니다. 같은 세션 ID가 여러 프로젝트에 있으면 표시된 프로젝트를 선택하고 연결합니다. 이미 알고 있는 Blackmagician 프로젝트 ID를 함께 입력할 수도 있습니다.

연결하면 **Blackmagician 모드**로 전환됩니다. 촬영 중 카메라 상태, Script 메모, 테이크 추가·수정·삭제를 자동으로 받아 로컬에 저장합니다. 초대 코드는 기존 NDJSON 이벤트 스트림을 계속 구독하고, 세션 ID는 전체 조회를 마친 뒤 3초 간격으로 다시 읽습니다. 네트워크·조회 시간에 따라 지연은 늘어날 수 있습니다. 브라우저 탭을 바꿔도 앱 서버가 실행 중이면 수신을 계속하고, 앱 서버를 재시작하면 수신 중이던 연결을 복원합니다. **수신 일시정지 / 수신 재개**로 제어할 수 있으며, 연결 상세의 **스냅샷 새로고침**은 전체 정보를 즉시 다시 읽습니다.

왼쪽에서 촬영 정보와 **확인할 촬영 정보**, 오른쪽에서 에이전트 대화를 봅니다. 좁은 화면에서는 두 보기를 탭으로 전환합니다. 에이전트에 “최근 테이크 결과와 메모를 알려줘”처럼 물으면 선택한 프로젝트의 최신 로컬 기록을 읽고 답합니다. **현재 촬영 정보**(`/shooting`)와 **빠진 기록 확인**(`/script-check`)은 모델 없이도 사용할 수 있습니다. 빈 씬·테이크 결과 및 기록 사본 충돌은 새 정보가 올 때마다 점검합니다. 확인 내용을 저장하면 로컬 메모로 남고, 원격 기록과 같은 값이 도착했는지 또는 원본이 변경·삭제됐는지 구분합니다.

이 버전은 원격 기록을 자동 수정하지 않습니다. 후속 Blackmagician 스크립터 보조 모드를 위한 [실시간 연동 규약](blackmagician-live-mode.md)에 질문·확인 메모와 충돌 처리 구조를 정리했습니다.

연결 중단과 자격 만료는 마지막 저장 상태로 표시합니다. 35초 이상 수신 근거가 없으면 실시간 상태를 해제하며, 401/403/404/410은 새 연결을 요구합니다. 종료된 세션도 후속 메모를 약 15초 간격으로 다시 읽습니다. 카메라 자체의 heartbeat와 이 Mac의 서버 수신 시각은 구별해야 하며, 수신 성공이 물리 카메라의 현재 접속을 보증하지는 않습니다.

**백업 검토**는 이 Data Handler 프로젝트의 완료 기록과 촬영 클립을 대조합니다. **에이전트로 검토**는 같은 프로젝트의 새 대화에 `/backup-review`를 준비하며 전송하면 근거별 결과를 받습니다. 에이전트에 “모든 클립이 제대로 백업됐는지 검토해줘”라고 요청할 수도 있습니다. 검토는 복제를 시작하거나 카메라를 제어하지 않습니다.

## 판정 근거

- `clipName`과 완료 manifest의 실제 파일명 또는 미디어 확장자를 제외한 이름을 대조합니다. 숫자·타임코드·clipToken으로 파일명을 추측하지 않습니다.
- 두 개 이상 복제 위치 각각의 검증 완료 상태, 원본과 일치하는 SHA-256, 현재 파일의 존재와 크기가 모두 확인돼야 검증 근거 일치로 표시합니다.
- 이름 중복, 촬영 기록 두 사본의 충돌, 체크섬 누락·불일치, 완료 artifact 없음, 다른 작업의 manifest, 볼륨·파일 접근 불가는 확인 필요입니다.
- 모든 기록이 일치해도 판단 범위는 **이 세션에 기록된 클립**입니다. 기록하지 않은 촬영과 별도 오디오의 완전성을 보증하지 않습니다.
- 체크섬은 **복제 완료 당시의 검증**입니다. 검토할 때 현재 미디어 전체를 다시 해시하지 않으므로 같은 크기의 사후 변조까지 재검증한 결과는 아닙니다.
- 현재 카메라 FPS·ISO를 과거 테이크의 촬영 설정으로 적용하지 않습니다.

새 복제 작업은 `.pipeline/runs/<run_id>/blackmagician/manifest.json`에 파일별 근거를 보존합니다. 이전 작업은 기존 manifest가 해당 job ID와 일치할 때만 사용합니다. 다음 카드가 덮어쓴 manifest는 이전 카드의 성공 근거로 사용하지 않습니다.

## 연결과 저장

세션 ID 방식은 가이드의 Firestore REST 경로를 사용합니다. 프로젝트·기록 페이지를 끝까지 읽고 `sessionId`가 일치하는 영구 기록을 가져옵니다. 원본 문서 키는 전체 경로이며 `takeId` 또는 레거시 문서 ID로 중복 제거하고 충돌을 보존합니다. 프로젝트가 많을수록 최초 세션 ID 탐색은 오래 걸릴 수 있으므로 프로젝트 ID를 지정하면 바로 조회합니다.

초대 코드는 기존 `/api/join`과 `/api/events`를 사용합니다. 최초 연결에서 전체 스냅샷을 얻은 뒤 전용 백그라운드 구독을 유지합니다. 재연결마다 카메라·Script·전체 기록·접근 상태를 모두 받아야 새 상태를 확정합니다. 전체 entries 이벤트는 기존 목록을 교체하므로 삭제와 과거 수정도 반영됩니다. EOF와 일시적인 네트워크 오류는 1~30초 지수 간격으로 재접속하며, 새로운 join 없이 기존 자격을 재사용합니다. 스트림 heartbeat는 전송 상태만 갱신하고 관측 시각이나 기록 버전을 만들지 않습니다. `/api/join`은 Host 참여 요청을 만들고 일회용 코드의 사용 횟수를 소비하므로 읽기 재시도에는 이미 발급된 자격을 재사용합니다. Host 편집 승인은 메타데이터 조회에 필요하지 않습니다.

연결 상태, 자격과 원본 문서는 `.pipeline/blackmagician/<local_project_id>/state.json`에 0600 권한으로 저장합니다. 앱의 JavaScript와 모델에는 Bearer 토큰을 전달하지 않습니다. 검토 근거는 같은 폴더의 `review.json`입니다. 연결 해제는 `/api/leave`를 시도하고 실패하면 0600 `leave.pending.json`에 보존해 다음 연결 동작에서 재시도합니다. 원격 자격은 서버의 만료 정책도 따릅니다.

기본 macOS 앱의 `.pipeline`은 `~/Library/Application Support/Data Handler/.pipeline`입니다. 기본 운영 Firebase 프로젝트는 `black-magician-2bc98`, API는 `https://blackmagician-web.vercel.app`입니다. Firebase Admin 개인키나 새 서버 배포는 필요하지 않습니다. 운영 서버의 공개 읽기 규칙 변경이나 인증 제한이 있으면 앱에서 접근 오류를 표시합니다.

## 생성한 테스트 샌드박스

사용자 요청에 따라 별도 로컬 Firestore 에뮬레이터와 **Blackmagician 저장소의 원본 API 구현**으로 만든 테스트 세션입니다. 운영 Firebase 세션이나 물리 카메라를 생성한 것으로 해석하지 않습니다.

| 항목 | 값 |
| --- | --- |
| Blackmagician 웹 | `http://127.0.0.1:8899` |
| Data Handler 테스트 앱 | `http://127.0.0.1:8890` |
| Firebase 에뮬레이터 | `127.0.0.1:8299` |
| Firebase 테스트 프로젝트 | `demo-datahandler-blackmagician` |
| Blackmagician 프로젝트 ID | `datahandler-sandbox-20260911` |
| 세션 ID | `DH-SANDBOX-0911` |
| 초대 코드 | `DH11-TEST` (생성 후 24시간) |
| 촬영 기록 | `A001_C001` ~ `A001_C003`, 3개 |

테스트용 Data Handler만 `DATA_HANDLER_BLACKMAGICIAN_SANDBOX=1`로 실행합니다. 이 값은 정해진 루프백 주소만 사용하며 기본 앱의 운영 연결을 바꾸지 않습니다. 테스트 로컬 에이전트는 8896 포트를 사용하고 Telegram은 연결하지 않았습니다. 에뮬레이터 종료 시 원격 샌드박스 데이터는 메모리에서 사라지지만 로컬 검증 산출물은 남습니다.

재현 도구:

```sh
# Firestore 에뮬레이터를 demo-datahandler-blackmagician / 8299 포트로 먼저 실행합니다.
FIRESTORE_EMULATOR_HOST=127.0.0.1:8299 node script/blackmagician_sandbox.mjs /path/to/blackmagician --seed
# 이미 만들어진 세션은 --seed 없이 API를 다시 실행합니다.
PYTHONPATH=. .pipeline/agent-venv/bin/python script/verify_blackmagician.py --output .pipeline/blackmagician-new-verification
```

검증은 새로 생성한 짧은 테스트 영상만 복제합니다. 두 카드 작업 후 모든 클립의 두 복제본 일치, 빠진 클립, 사라진 복제본, 앱·에이전트 결과, 과거 메모 수정, 삭제 반영, 재조회 중복 방지, 종료 세션 이력을 확인합니다. 실제 운영 API·물리 카메라 연결은 이 샌드박스 검증 범위에 포함되지 않습니다.

이번 통합 근거: `.pipeline/blackmagician-qa-20260911/verification.json`. 테스트: `.pipeline/agent-venv/bin/python -m pytest orchestrator/tests`.
