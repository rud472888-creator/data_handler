# Data Handler DIT

프로젝트 → 촬영일 → 카드 중심의 macOS용 작업 공간입니다. 기존 DataManager의 검증 복사와 DataHelper의 PDF 생성을 연결합니다. DIT의 새 저장 구조를 위해 DataManager 복사 경로 처리를 연결했습니다. 기존 작업 기록의 경로는 유지됩니다.

## 실행

```sh
python -m orchestrator.cli app --host 127.0.0.1 --port 8750
```

브라우저에서 `http://127.0.0.1:8750`을 엽니다. 다른 앱과 포트를 분리하려면 `python -m orchestrator.dit_app --port 8751`을 사용합니다.

별도 macOS 앱과 DMG:

```sh
APP_NAME='Data Handler DIT' BUNDLE_ID='com.dit.data-handler.workspace' ./script/package_macos_app.sh
```

결과는 `dist/Data Handler DIT.app`, `dist/Data Handler DIT.dmg`입니다. macOS 패키지에서는 기본 폴더 선택 창을 사용할 수 있습니다. 개발 브라우저에서는 연결 볼륨 자동완성 또는 직접 경로 입력을 사용합니다.

## 사용 흐름

1. **새 프로젝트**에서 이름만 입력합니다. 프로젝트 생성 시 외장 디스크에 폴더를 만들지 않습니다.
2. **카드 가져오기**에서 촬영일, 카메라, 원본 폴더, 두 복제 위치를 선택합니다.
3. **경로 확인**에서 프로젝트와 최종 복사 위치를 확인한 뒤 복사를 시작합니다. 파일은 `프로젝트/001_Footage/R#n/` 바로 아래에 저장됩니다. 날짜·카메라는 작업 기록으로만 남고, `R#n`은 프로젝트 전체에서 연속 증가합니다. 원본 안의 하위 폴더는 유지하며 `source-path-1` 같은 내부 식별자 폴더는 만들지 않습니다.
4. 카드를 선택하면 원본, 복제 위치, 체크섬 검증, PDF, 실패 사유를 확인할 수 있습니다.
5. **PDF 리포트**에서 현재 프로젝트·촬영일의 PDF를 모아 보고 앱 내 미리보기로 엽니다.

## 상태의 의미

복사 엔진의 완료 이벤트가 `completed`이고 `replicas_complete=true`일 때만 체크섬 검증 완료로 표시합니다. PDF 생성 실패는 복사 검증 결과와 별도로 표시합니다. 파일이 없어지거나 볼륨이 연결되지 않은 리포트는 링크 대신 해당 사유를 표시합니다.

UI는 10초마다 기록을 다시 읽습니다. 실제 복사 바이트, 속도, ETA를 측정하지 않으며 추정 진행률을 표시하지 않습니다. 화면의 마지막 작업 기록은 엔진 기록 시각이고, 기록 확인 시각은 UI 조회 시각입니다. 각 복제본의 개별 진행률은 현재 엔진의 완료 이벤트만으로 판단하지 않습니다.

라이브러리는 기존 `console-registry.json`과 `.pipeline/runs` 기록을 사용합니다. 프로젝트 상단의 **프로젝트 제거**를 누르면 확인 후 목록에서 숨깁니다. 원본·백업·PDF·작업 기록은 보존하고, 제거 직후 **되돌리기**로 복원할 수 있습니다. 진행 중이거나 완료를 확인하지 못한 작업이 있으면 제거할 수 없습니다. 기존 백업 폴더는 자동 이동하거나 변환하지 않습니다. 기존 앱 프런트는 `orchestrator.app_front.server:create_app` 팩토리로 남아 있습니다.

## 검증

```sh
python -m pytest orchestrator/tests
```

`test_dit_workspace.py`는 디스크 없는 프로젝트 생성·재열기, 경로 검토와 실행 연결, 실패 상태, 없는 PDF, 실제 테스트 영상 두 복제본의 SHA-256 일치와 PDF 응답을 검증합니다.

첫 버전 범위에 LUT, 색보정, 클립 재생, 프록시 변환, 작업 취소·재개는 포함하지 않습니다.
