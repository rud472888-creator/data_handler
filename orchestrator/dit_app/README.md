# Data Handler DIT

프로젝트 → 촬영일 → 카드 중심의 macOS용 작업 공간입니다. 기존 DataManager의 검증 복사와 DataHelper의 PDF 생성을 연결합니다. DIT의 새 저장 구조를 위해 DataManager 복사 경로 처리를 연결했습니다. 기존 작업 기록의 경로는 유지됩니다.

작업 공간에서 오른쪽 **에이전트 검토**가 완료 후 복제 근거, 보고서 오류·추천 행동, 연결된 Blackmagician의 해당 릴 촬영 기록을 검토합니다. 단계마다 과거 대화가 없는 새 세션으로 실행하고 **다시 검토**로 재시도할 수 있습니다. [동작·한계·검증 기록](../../docs/completion-agent-reviews.md).

프로젝트 상단 **Blackmagician**에서 초대 코드 또는 세션 ID를 연결하면 전용 촬영 모드로 전환됩니다. 촬영 중 들어오는 카메라·Script·테이크를 자동으로 받고, 같은 화면의 로컬 에이전트에게 질문하거나 빠진 기록에 확인 메모를 남길 수 있습니다. 클립별 백업 근거 대조도 연결 상세에서 사용할 수 있습니다. 연결·에이전트 검토·샌드박스 사용법은 [Blackmagician 연동](../../docs/blackmagician-integration.md)을 참고하세요.

## 실행

```sh
python -m orchestrator.cli app --host 127.0.0.1 --port 8750
```

브라우저에서 `http://127.0.0.1:8750`을 엽니다. 다른 앱과 포트를 분리하려면 `python -m orchestrator.dit_app --port 8751`을 사용합니다.

별도 macOS 앱과 DMG:

```sh
APP_NAME='Data Handler DIT' BUNDLE_ID='com.dit.data-handler.workspace' ./script/package_macos_app.sh
```

결과는 `dist/Data Handler DIT.app`, `dist/Data Handler DIT.dmg`입니다. macOS 패키지에서는 기본 폴더 선택 창을 사용할 수 있습니다. 개발 브라우저에서는 연결 볼륨 자동완성 또는 직접 경로 입력을 사용합니다.

## 사용 흐름

1. **새 프로젝트**에서 이름만 입력합니다. 프로젝트 생성 시 외장 디스크에 폴더를 만들지 않습니다.
2. **카드 가져오기**에서 촬영일, 카메라, 원본 폴더와 백업 경로를 선택합니다. 경로는 1개로 시작하며 **백업 경로 추가**와 각 행의 **삭제**로 개수 제한 없이 조정합니다. 1:1, 1:100 모두 지원하고 최소 1개는 유지합니다. 추가한 경로마다 macOS 폴더 선택 창을 사용할 수 있습니다.
3. **경로 확인**에서 프로젝트와 최종 복사 위치를 확인한 뒤 복사를 시작합니다. 파일은 `프로젝트/001_Footage/R#n/` 바로 아래에 저장됩니다. 날짜·카메라는 작업 기록으로만 남고, `R#n`은 프로젝트 전체에서 연속 증가합니다. 원본 안의 하위 폴더는 유지하며 `source-path-1` 같은 내부 식별자 폴더는 만들지 않습니다.
4. 카드를 선택하면 오른쪽 에이전트 검토에서 해당 카드의 검토 근거와 추천 행동을 확인할 수 있습니다. 별도의 카드 상세 패널은 사용하지 않습니다.
5. **PDF 리포트**에서 현재 프로젝트·촬영일의 PDF를 모아 보고 앱 내 미리보기로 엽니다.
6. **PDF 리포트** 상단의 **촬영일 DIT 리포트**에서 **생성·열기**를 누르면 그날의 모든 카드(카메라, 원본, 파일 수, 용량, 체크섬 검증, 상태, 백업 위치, 카드 리포트)를 한 장으로 정리한 PDF를 만들고, 연결된 모든 백업의 `프로젝트/00_Master/reports/DIT_Report_<촬영일>.pdf`에 저장합니다.

카드별 리포트는 `프로젝트/00_Master/reports/R#n/` 아래에 저장되어 다음 카드가 이전 카드의 리포트를 덮어쓰지 않습니다. 체크섬 PDF와 manifest는 모든 백업에 함께 저장되고, 클립 검수 PDF는 백업마다 생성됩니다(동시에 최대 4개, `DATA_HANDLER_REPORT_WORKERS`로 조정). 검수가 끝나면 외부 watcher 없이도 `final-report.md`를 쓰고 작업을 완료 상태로 닫습니다. 다음 카드를 가져올 때는 직전 카드의 백업 경로와 카메라가 자동으로 채워집니다.

## 상태의 의미

복사 엔진의 완료 이벤트가 `completed`이고 `replicas_complete=true`일 때만 체크섬 검증 완료로 표시합니다. PDF 생성 실패는 복사 검증 결과와 별도로 표시합니다. 파일이 없어지거나 볼륨이 연결되지 않은 리포트는 링크 대신 해당 사유를 표시합니다.

UI는 10초마다(창이 다시 보일 때는 즉시) 기록을 다시 읽고, 바뀐 내용이 있을 때만 화면을 다시 그립니다. 카드 목록에는 검토 요약만 담고, 선택한 카드의 검토 항목은 따로 불러옵니다. 실제 복사 바이트, 속도, ETA를 측정하지 않으며 추정 진행률을 표시하지 않습니다. 화면의 마지막 작업 기록은 엔진 기록 시각이고, 기록 확인 시각은 UI 조회 시각입니다. 각 복제본의 개별 진행률은 현재 엔진의 완료 이벤트만으로 판단하지 않습니다.

라이브러리는 기존 `console-registry.json`과 `.pipeline/runs` 기록을 사용합니다. 프로젝트 상단의 **프로젝트 제거**를 누르면 확인 후 목록에서 숨깁니다. 원본·백업·PDF·작업 기록은 보존하고, 제거 직후 **되돌리기**로 복원할 수 있습니다. 진행 중이거나 완료를 확인하지 못한 작업이 있으면 제거할 수 없습니다. 기존 백업 폴더는 자동 이동하거나 변환하지 않습니다. 기존 앱 프런트는 `orchestrator.app_front.server:create_app` 팩토리로 남아 있습니다.

## 검증

```sh
python -m pytest orchestrator/tests
```

`test_dit_workspace.py`는 디스크 없는 프로젝트 생성·재열기, 경로 검토와 실행 연결, 실패 상태, 없는 PDF, 실제 테스트 영상의 1개·2개·100개 복제본 SHA-256 일치와 PDF 응답을 검증합니다. 에이전트 계획과 Blackmagician 검토도 지정한 모든 경로를 대상으로 검증합니다.

첫 버전 범위에 LUT, 색보정, 클립 재생, 프록시 변환, 작업 취소·재개는 포함하지 않습니다.
